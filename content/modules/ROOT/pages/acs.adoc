== Feature Overview

Red Hat Advanced Cluster Security (ACS) 5 introduces several new capabilities for securing containerized and virtualized workloads:

. *VM Vulnerability Management* — extends RHACS vulnerability scanning to cover virtual machine workloads running on OpenShift Virtualization. The `roxagent` binary runs inside VMs, scans installed packages (RPM/DNF), and reports vulnerabilities to ACS Central via the collector relay over VSOCK. Organizations gain unified vulnerability visibility across both containers and VMs from a single ACS console.

. *File Activity Monitoring (FAM)* — provides runtime file integrity monitoring. Security teams can define custom file paths (with wildcard support) to monitor for access, modification, and rename operations. File activity criteria can be combined with process-level criteria (process name, ancestor, arguments, UID) in deployment and node policies, enabling detection of unauthorized file access patterns required for compliance frameworks such as PCI-DSS.

. *Init Container Security Coverage* — RHACS now evaluates init containers for both image scanning and security policies. When a deployment references init containers, their images are scanned for vulnerabilities using the same process as main container images. Build and Deploy stage policies can be configured to include or exclude init containers using the "Filters" menu.

. *ACS MCP Server* — exposes ACS Vulnerability Management and Configuration Management APIs as MCP tools, allowing AI agents to interact programmatically with security data.

Each of these features is covered in more detail in the following sections. Part of each walkthrough will be to discuss how the feature is setup, how it works, and how it can be used to secure your environment.

*The ACS team asks that you provide feedback on the feature by completing the structured feedback form at the end of each exercise.*

== Hands-on Exercises

=== Exercise 1: VM Vulnerability Management

In this exercise you will walk through the ACS 5 vulnerability scanning capabilities for OpenShift Virtualization workloads.

==== Understanding the prerequisites for VM vulnerability scanning

Before you verify the prebuilt VM, review what RHACS requires to scan OpenShift Virtualization workloads. These conditions are already met in this lab for `rhel9-vm`.

For full product details, see the link:https://docs.redhat.com/en/documentation/red_hat_advanced_cluster_security_for_kubernetes/4.10/html-single/operating/index#scanning-virtual-machines_examine-images-for-vulnerabilities[Scanning virtual machines^] topic in the RHACS 4.10 Operating guide.

.How RHACS scans virtual machines

RHACS collects, processes, and analyzes VM package data with these components:

`roxagent`::
Binary that runs inside the VM. It scans installed packages, creates index reports, and sends them to the relay.

Relay::
Node-level Collector component that receives index reports over VSOCK and forwards them to Sensor.

Sensor::
Cluster-level component that aggregates VM data with Kubernetes API information and sends it to Central.

Central::
Stores VM information, matches packages against known CVEs (via Scanner V4), and exposes results in the RHACS portal and API.

.Prerequisites

OpenShift Virtualization and RHACS must meet the following requirements:

* The OpenShift Virtualization Operator is installed on the cluster you want to scan.
* The `HyperConverged` resource is patched to enable virtual socket (vsock) support.
* The RHACS feature flag `ROX_VIRTUAL_MACHINES=true` is set on the Central container, the Sensor container, and the Compliance container in the Collector pod.

Each VM to be scanned must meet the following requirements:

* The VM runs Red Hat Enterprise Linux (RHEL) and is registered with Red Hat Subscription Manager with an active RHEL subscription.
* VSOCK is enabled on the VM with `spec.domain.devices.autoattachVSOCK: true`.
* The VM has internet access to download repository-to-Common Platform Enumeration (CPE) mappings.
* DNF is installed.
* `roxagent` runs with privileges sufficient to scan package databases and send index reports over a privileged port (typically root or sudo).

==== Create and onboard a second VM (Optional)

In this optional path you deploy a second VirtualMachine from a declarative GitOps-style manifest, focus on the fields that matter for ACS vulnerability scanning, apply the YAML, then reach the guest web server.

IMPORTANT: Schedule the VM on a *worker* node. The ACS collector relay is not enabled on control-plane nodes by default.

. Review the VirtualMachine manifest sections that matter for ACS vulnerability scanning:
+
* *VSOCK* — `spec.template.spec.domain.devices.autoattachVSOCK: true` so `roxagent` can send index reports to the collector relay.
* *RHEL guest with subscription and DNF* — ACS VM scanning supports RHEL packages indexed by DNF with valid repository links. Cloud-init registers the guest and enables RHEL repos so scans can map packages to CVEs.
* *`roxagent` in the guest* — cloud-init runs `init-vm.sh`, which installs `roxagent` and schedules it to report package inventory to ACS.
+
[source,yaml]
----
devices:
  autoattachVSOCK: true
----

. Apply the VirtualMachine manifest (the same GitOps example stored at `acs-virt/examples/rhel-webserver-vm.yaml` in https://github.com/rhpds/ocp5-ea-gitops[ocp5-ea-gitops^]):
+
[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: rhel-webserver
  namespace: acs-virt
  labels:
    app: rhel-webserver
spec:
  runStrategy: Always
  template:
    metadata:
      labels:
        kubevirt.io/domain: rhel-webserver
        kubevirt.io/size: small
    spec:
      domain:
        cpu:
          cores: 1
          sockets: 1
          threads: 1
        devices:
          autoattachVSOCK: true
          disks:
            - bootOrder: 1
              disk:
                bus: virtio
              name: rootdisk
            - disk:
                bus: virtio
              name: cloudinitdisk
          interfaces:
            - masquerade: {}
              model: virtio
              name: default
          rng: {}
        features:
          acpi: {}
          smm:
            enabled: true
        firmware:
          bootloader:
            efi: {}
        machine:
          type: pc-q35-rhel9.6.0
        memory:
          guest: 2Gi
      networks:
        - name: default
          pod: {}
      terminationGracePeriodSeconds: 180
      volumes:
        - dataVolume:
            name: rhel-webserver-volume
          name: rootdisk
        - name: cloudinitdisk
          cloudInitNoCloud:
            userData: |-
              #cloud-config
              user: cloud-user
              password: redhat
              chpasswd: { expire: false }
              runcmd:
                - curl -k -o /tmp/katello-ca-consumer-latest.noarch.rpm https://demosat-ha.infra.demo.redhat.com/pub/katello-ca-consumer-latest.noarch.rpm
                - rpm -Uvh /tmp/katello-ca-consumer-latest.noarch.rpm
                - |
                  subscription-manager register \
                    --activationkey="demosat-smt-lb1161-wolfgang" \
                    --org="Red_Hat_RHDP_Labs" \
                    --name="rhel-webserver-68q9h-2" \
                    --force
                - subscription-manager release --set=10
                - |
                  subscription-manager repos \
                      --enable=rhel-10-for-x86_64-baseos-rpms \
                      --enable=rhel-10-for-x86_64-appstream-rpms
                - curl -sL -o /tmp/init.sh https://raw.githubusercontent.com/rhpds/sovereign-cloud-showroom/refs/heads/main/scripts/init-vm.sh
                - chmod +x /tmp/init.sh
                - /tmp/init.sh
                - systemctl enable --now httpd
                - echo '<h1>rhel-webserver</h1><p>ACS VM scanning demo</p>' > /var/www/html/index.html
                - echo "Setup complete"
  dataVolumeTemplates:
  - metadata:
      name: rhel-webserver-volume
    spec:
      sourceRef:
        kind: DataSource
        name: rhel10
        namespace: openshift-virtualization-os-images
      storage:
        resources:
          requests:
            storage: 30Gi
EOF
----

You should see an HTTP `200` response and a short HTML page that identifies `rhel-webserver`.

If `curl` fails, open the guest console (*Virtualization > VirtualMachines > rhel-webserver > Console*) and log in to check cloud-init and `httpd`:

Username:
+

Allow several minutes after the first successful `roxagent` run for results to show.

== Key Takeaways

* ACS 5 extends security coverage beyond containers to virtual machines running on OpenShift Virtualization
* roxagent communicates with the collector via VSOCK, requiring no network configuration inside the VM
* File activity monitoring provides visibility into security-relevant file access patterns
* The ACS MCP server enables AI agents to query and act on security data programmatically
